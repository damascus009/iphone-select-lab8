# iPhone Select — ЛР8, інтерактивне розбирання iPhone

Продовження готового сайту ЛР6 зі збереженням темного Burgundy-дизайну.

## Запуск проєкту

Для локального запуску використовується HTTP-сервер:

```bash
python3 -m http.server 8077
```

Відкрити в браузері: http://localhost:8077/

Не використовувати `file://`, оскільки JavaScript ES-модулі потребують HTTP-середовища.

## Основні можливості

- Каталог iPhone 18 Pro та iPhone 18 Pro Max.
- Порівняння характеристик моделей.
- Інтерактивний 360° перегляд.
- Конфігуратор моделі, кольору та пам’яті.
- Навчальний розрахунок Trade-in.
- Інтеграції YouTube, Google Maps і валютного віджета.
- Адаптивний інтерфейс для комп’ютерів і мобільних пристроїв.

Характеристики моделей наведено за джерелом: https://www.apple.com/iphone-18-pro/specs/

Ціни нових пристроїв не вказані. Trade-in виконує демонстраційний розрахунок, кошик працює як лічильник, а форма підписки не надсилає даних.

## Інтерактивний перегляд 360°

Для запуску необхідно натиснути кнопку **«Відкрити 360°»**.

Керування:
- Перетягування мишею або пальцем — обертання моделі.
- Стрілки — обертання та нахил.
- `+` / `−` — зміна масштабу.
- Коліщатко миші — масштабування над сценою.
- `Home` — повернення початкового ракурсу та збирання.
- `E` / «Розібрати iPhone» — рознесення деталей.
- `C` / «Зібрати iPhone» — повернення деталей.
- Наведення — підсвічування та назва; клік — опис компонента.
- Кнопки списку дають доступ до всіх деталей клавіатурою та на сенсорному екрані.
- `Escape` у сцені або × в панелі — закрити опис.

Використовується Three.js 0.187.0. JavaScript-модулі та 3D-модель завантажуються локально після натискання кнопки.

### Виправлення завантаження 360°

Виявлено проблему із завантаженням модулів Three.js на Netlify: код звертався до файлів у папці `vendor/three/build/`, хоча модулі розміщувалися безпосередньо у `vendor/three/`.

Для виправлення узгоджено шляхи імпорту з фактичною структурою проєкту:

- `vendor/three/three.module.js`
- `vendor/three/three.core.js`
- `vendor/three/addons/loaders/USDLoader.js`

Проблему шляхів до модулів виправлено без зміни дизайну та принципу роботи 360° Viewer.

У ЛР7 модель завантажувалась із `assets/models/`. У ЛР8 `viewer-model.js` будує одну компонентну модель процедурно. Оригінальний USDZ залишено без змін; активний переглядач його не завантажує.

Колір конфігуратора не змінює матеріали 3D-моделі. 34 інтерактивні групи (включно з шарами дисплея, опорними пластинами, окремими камерами й оптикою): дисплей, акумулятор із випарною камерою, плата, процесор і екрани, задні камери та захисні вікна, фронтальна камера, Face ID, рама, задня панель, два динаміки, Taptic Engine, USB-C, мікрофон, зарядна котушка, антена, шлейфи, накладки, кріплення та два ущільнювальні контури.

Це **навчальний макет за Apple Repair Manual**, а не виробничий CAD. Основні зони вузлів звірено з Internal View; дрібна геометрія, матеріали та маршрути шлейфів схематичні; непідтверджені ємність, потужність, роздільність і модель процесора не зазначаються. Зовнішність відтворено спрощено за референсами, без фотограмметричної точності оригінального USDZ.

Розбирання змінює позиції тих самих 3D-груп через `requestAnimationFrame`; вибір працює через `Raycaster`. Повторні команди змінюють ціль поточної анімації. `prefers-reduced-motion` вимикає інтерполяцію. `ResizeObserver` адаптує камеру; поза видимою областю рендер призупиняється. Втрата WebGL-контексту повертає кнопку повторного запуску. Ресурси та слухачі звільняються при помилці й виході зі сторінки.

## Перевірка ЛР8 (08.11.2026)

- Проаналізовано `model.usda` всередині USDZ: під `xYOCLbDjKmKlJoU` дві гілки `UBGArkKGrAMRRnj` та `wUOhcMgiBmCgGaw` із повтореною ієрархією. Вихідний переглядач показував два телефони. Імена внутрішніх вузлів обфусковані; підтвердженої компонентної карти немає.
- У браузері перевірено запуск, одну сцену/один canvas, усі дев’ять доступних компонентів, розбирання до 1.000 та збирання до 0.000, зміну напрямку анімації повторними командами.
- Перевірено клавіатурні обертання, масштаб, скидання, вибір процесора кліком на геометрії через Raycaster і кнопкою списку.
- Перевірено ширини 1365, 390 та 320 px; горизонтального переповнення документа немає.
- Збережено справжні знімки початкової моделі, нового телефона, розбирання, панелі та мобільної сцени окремо від публічного сайту.
- Режим reduced motion, втрата WebGL і відсутні модулі обробляються кодом, але примусове відтворення цих умов у браузері не виконувалось. Фізичний сенсорний пристрій не тестувався.
- Під час тривалої перевірки журнал браузера показав два повідомлення про MutationObserver без URL джерела. У коді сайту такого API немає; походження повідомлень не встановлено. Помилок із префіксом `iPhone 360:` не було.
- Решта секцій, сторонні ресурси й попередні звіти не змінювались. Новий деплой і злиття в main не виконувались.


## Уточнення моделі (10.11.2026)

Доопрацьовано існуючу процедурну модель та переглядач. Замкнений периметр рами й узгоджені площини дисплея та задньої панелі усувають видиму наскрізну щілину. Камерні вікна мають низький рельєф; Burgundy приглушений, освітлення нейтральне. Додано кнопку «Збоку» та посилання на джерело в описі кожної групи.

Джерела та обмеження: [MODEL-NOTES.md](MODEL-NOTES.md). Розбирання поетапне, з точним поверненням до незмінних початкових координат. Батарея й прикріплена випарна камера рухаються разом. Це огляд компонентів, не інструкція ремонту.

Автоматизовані браузерні перевірки запускаються через локальний HTTP-сервер:

- `/tests/viewer-geometry.html`: 24 групи, 20 циклів збирання (480 точних повернень), одиничні нормалі, скінченні вершини, 20 променів через боковини, відсутність перетину основних об’ємів плати й батареї.
- `/tests/viewer-interaction.html`: усі 24 вибори, клавіатурний масштаб, ракурс 90°, скидання, reduced motion, повторне завантаження й відновлення після синтетичної події втрати контексту.
- `/tests/viewer-interaction.html?mode=no-webgl`: доступність повторного запуску та відсутність покинутого canvas після відмови WebGL.

Усі перелічені перевірки пройдено. 67 730 трикутників; об’єднання геометрії в межах груп скоротило 424 сітки до 83. Тіньовий прохід додає виклики рендерингу; ці цифри не є вимірюванням FPS. Фізичний сенсорний пристрій і справжня втрата GPU не тестувалися.

## Лабораторна №9 — форма зворотного зв’язку

Секція `#feedback`: ім’я, email, телефон, повідомлення, згода. HTML/Tailwind і Vanilla JS; залежності для роботи готового сайту не потрібні. Форма не надсилає даних та не використовує localStorage. Кнопка без JavaScript вимкнена. Після успіху відкривається `<dialog>`; закриття очищає поля й повертає фокус.

- `assets/js/validation-rules.mjs`: окремі чисті валідатори, 2 RegEx.
- `assets/js/validation.js`: blur/input/change/submit, повідомлення, ARIA, діалог.
- `assets/css/feedback.css`: стани, спеціальні стилі діалогу.
- Правила: ім’я 2–80 символів; email — спрощений формат до 254; телефон строго +380 та 9 цифр без нормалізації; повідомлення 10–2000 символів; згода обов’язкова. Довжина імені/повідомлення рахується Unicode-кодовими точками після trim. Цифри/спецсимволи не заборонені поза цими правилами.

Перевірки: `node tests/validation-rules.mjs` (36 випадків), `python3 tests/check-feedback.py` (потрібен lxml). Браузерні сценарії та скриншоти збережено окремо в матеріалах звіту.

Локально: `python3 -m http.server 8099`, відкрити http://localhost:8099/#feedback.
Стилі: `pnpm install --frozen-lockfile`, `pnpm run build:css`. Публікується вже зібраний статичний сайт.

Vercel: Framework Other; Root Directory `./`; Output Directory `.`; Build Command порожня; Install Command порожня. `vercel.json` містить статичні налаштування. Підключення GitHub має використовувати цей самий репозиторій. Не зберігайте ключі або токени в коді.

### Виправлення 360° після додавання форми — 14.11.2026

Модуль форми `assets/js/validation.js` опинився перед `importmap`. Firefox на наданому скриншоті не розпізнавав імпорт `three`, тому переглядач показував помилку замість моделі. У коміті `e8a32ef` карту імпортів перенесено в `<head>` перед усіма модульними скриптами. Геометрію моделі, Hero та стилі 360° не змінено; форму збережено.

Гілка `fix/360-feedback-compatibility` додає цей опис і посилює перевірку: одна карта імпортів у `<head>`, розташована перед кожним модулем, а її шлях `three` веде до наявного локального файла. Виправлення вже опубліковано окремим терміновим комітом; ця гілка фіксує перевірки та документацію через Pull Request у `main`.

Перевірено в локальному браузері: запуск 360°, обертання, розбирання та збирання; відображення п’яти помилок порожньої форми та діалог після правильного заповнення. Усі 36 перевірок валідаторів пройдено. Окремий Firefox тут не запускався; додано перевірку порядку скриптів, який спричинив помилку на скриншоті.

Робоча папка для VS Code: `lab7/site`. Перед вирівнюванням історії створено резервні гілки `backup/lab9-before-360-fix` та `backup/360-fix-local-history`; файли збережено. Запускайте сайт через HTTP (Live Server або локальний сервер), після оновлення перезавантажте сторінку без кешу.
